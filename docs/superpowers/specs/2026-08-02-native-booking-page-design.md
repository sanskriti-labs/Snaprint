# Native Booking Page (`/book`)  --  Design Spec

## Problem

"Book a Demo" currently links out to `book.sanskritilabs.in`, which renders the stock Easy!Appointments (EA) UI: default green theme, "Powered By Easy!Appointments" footer, a stray admin "Login" button, and no mobile optimization. This is the highest-intent moment in the funnel (a visitor who clicked to book a call) and it hands them an unbranded, unpolished experience that undercuts trust built up by the rest of the site.

## Goal

Replace the outbound link with a native `/book` page on `snaprints.com`, styled to match the existing design system, that talks to Easy!Appointments only through its REST API  --  the visitor never sees EA's UI.

## Architecture

- **New page:** `app/book/page.tsx`. Styled with existing tokens: Space Grotesk display font, `#E63946` accent, dark gradient treatment consistent with `CtaFinal`/`Hero`.
- **Two server-side Next.js API routes** proxy to EA so the API key never reaches the browser:
  - `GET /api/book/availability?date=YYYY-MM-DD` → calls EA `GET /api/v1/availabilities`, returns open slot times for that date.
  - `POST /api/book/submit` → calls EA `POST /api/v1/appointments` with `{ name, email, phone, date, time }`, returns success/failure.
- Service (`Introduction Call with Snaprint Founder`) and provider (`Any Provider`) are fixed server-side inside the API routes  --  never user-facing choices, since there's only one offering today.

## Flow on `/book`

1. Calendar showing the next ~30 days; days EA reports as fully booked/closed are disabled.
2. Selecting a date fetches that day's slots via `/api/book/availability`; slots render as buttons (e.g. "3:00 PM").
3. Selecting a slot reveals name/email/phone fields plus a "Confirm Booking" button.
4. On submit, `/api/book/submit` creates the appointment in EA. On success, the form is replaced in-page with a confirmation state ("You're booked for Tue Aug 4, 3:00 PM  --  check your email"). EA's own confirmation email still fires as it does today  --  no extra email logic on our side.
5. On error (slot taken between load and submit, network failure, EA down), show an inline error with a retry action. The `snaprints@sanskritilabs.in` email link stays visible throughout as a fallback.

## Data & secrets

- `EA_API_KEY` is added as an encrypted Vercel environment variable, read only inside the two server-side API routes.
- No EA calls are ever made from the browser; the key is never shipped client-side.
- The EA API key itself must be generated by the site admin in the EA admin panel (Settings → API → Generate), then pasted into Vercel  --  it cannot be fabricated externally, since EA validates against its own stored hash.

## Site changes

- `components/sections/CtaFinal.tsx`  --  "Book a Demo" link (`href="https://book.sanskritilabs.in"`, currently `target="_blank"`) changes to `href="/book"`, `target="_blank"` removed (in-site navigation now).
- `components/sections/MachineSpecs.tsx`  --  same "Book a Demo" link update.
- `book.sanskritilabs.in` (the EA instance) keeps running unchanged in the background  --  it remains the actual booking engine and admin panel. It's simply no longer linked from the marketing site.

## Out of scope

- Rescheduling/cancellation UI  --  EA's own confirmation emails already contain manage-booking links.
- Multi-service selection  --  only one service exists today.
- Timezone handling beyond what EA reports  --  single timezone (IST) assumed.
- Any change to the EA admin/backend configuration itself (services, working hours, etc.)  --  that stays managed in the EA admin panel as today.

## Open verification item for implementation

EA's `GET /api/v1/availabilities` and `POST /api/v1/appointments` endpoints were not confirmed against an authenticated response during design (no API key available yet). Implementation should verify exact request/response shapes against the live EA instance once `EA_API_KEY` is available, and adjust the API route implementations if the response format differs from EA's documented v1 API.
