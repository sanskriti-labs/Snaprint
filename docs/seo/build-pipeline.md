# Build pipeline — auto-generating `bodies.ts`

## The problem this solves

`content/pseo/bodies/*.md` (145 files) are the **source of truth** for pSEO page
bodies. React can't read them at runtime, so `scripts/build-bodies-ts.mjs`
compiles them into a typed map at `content/pseo/bodies.ts`.

That generated file used to be regenerated by hand. Edit a `.md`, forget the
script, and the build silently ships the *old* prose — no error, no warning,
just stale pages. The hooks below make that failure mode impossible.

## What runs when

| Command | Chain |
|---|---|
| `pnpm run build` | `build:bodies` → `verify:pseo` → `next build` |
| `pnpm run dev` | `predev` (→ `build:bodies`) → `next dev` |
| `pnpm install` | `prepare` (→ `build:bodies`, non-fatal) |

`build:bodies` is the single named entry point (`node scripts/build-bodies-ts.mjs`);
every hook delegates to it, so the command lives in exactly one place.

### Ordering note

`build:bodies` runs **before** `verify:pseo`, not after. The verifier gates
content correctness, so it must inspect freshly generated data — swapping the
order would validate the previous run's output.

### `predev`

npm/pnpm lifecycle convention: `pre<name>` runs automatically before `<name>`.
Verified working under pnpm 11.9.0 as configured in this repo. If a future pnpm
upgrade or an `.npmrc` setting `enable-pre-post-scripts=false` disables that
convention, `predev` stops firing silently — fold it into `dev` explicitly if
stale dev data ever reappears.

### `prepare`

Runs after `pnpm install`, covering fresh clones. **`content/pseo/bodies.ts` is
currently untracked**, so on a clean checkout it will not exist until something
generates it — `prepare` is what makes `pnpm install && pnpm dev` work on a new
machine, not merely defensive.

It ends in `|| true` deliberately. `prepare` also fires in contexts where the
content tree may be absent or partial (e.g. installing this package as a
dependency); a hard failure there would break `pnpm install` itself. A stale or
missing `bodies.ts` is caught moments later by `build`, which does **not**
tolerate failure. Fail loudly at build, never at install.

## Idempotency

The script is a pure function of the `.md` files: it rewrites `bodies.ts` from
scratch each run. Two consecutive runs produce byte-identical output (hash
verified), so the extra invocations cost nothing and never produce spurious
diffs.

## Skipping regeneration

Run the underlying tool directly:

```bash
npx next build     # no bodies regen, no verifier
npx next dev
```

Useful when debugging a build issue unrelated to content. Note you also lose the
`verify:pseo` gate, so don't ship from that path.

## Editing content

```bash
vim content/pseo/bodies/<kind>-<slug>.md   # edit source of truth
pnpm run dev                               # bodies.ts regenerates automatically
```

Never hand-edit `content/pseo/bodies.ts` — it carries a generated-file banner and
the next build overwrites it.

## Failure modes

The script throws (and fails the build) when a `.md` is missing required
frontmatter — `kind`, `slug`, or `name`:

```
Error: Missing frontmatter in area-foo.md: kind=area slug=foo name=undefined
```

Fix the frontmatter in the named file; there is no way to skip a malformed entry.
